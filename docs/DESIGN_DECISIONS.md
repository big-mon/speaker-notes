# 現在の構成を選んだ理由

## 要約の元資料を作るCLI

目的は、日本語ポッドキャストの主張・理由・具体例を読み取り、価値あるシーンへ戻れる元資料を作ることです。話者付き議事録の完全再現は必須ではありません。話者を決められない内容も匿名で利用できるため、帰属を推測して埋めるより、原文と確認箇所を残します。GUIはこの目的に不要と判断し、テキストとJSONを後段エージェントへ渡します。

## Qwen本文とApple照合

対象1話を用いた意味抽出の定性的比較では、Qwen3-ASR-1.7B BF16の原文が主張から理由・対比・具体例へのつながりを追いやすく、ユーザーの判断で主ASRに採用しました。Cohereには読みやすい表記でも比較の結論や理由が抜ける箇所があり、Parakeetを含む候補の追加検証は終了しました。別音源での一般的な精度順位や、全文聴取による正解率を示す判断ではありません。

Appleは人名・用語などでQwenと異なる読みを得られるため、誤りの発見を助ける補助ASRとして残します。一致は正解の証明にならず、不一致のどちらが正しいかも自動では決められないので、本文の自動置換には使いません。人が訂正した固有名詞を全文置換する処理も採用しません。

## VAD分割と時刻

長い連続入力を単純な固定秒数で切ると発言の途中に当たりやすいため、VADの短い休止候補へ分割点を寄せます。最大180秒はQwenのアラインメントと組み合わせて検証した上限です。発話中には分割しないという保証ではなく、候補がない場合の切点は未解決として残します。

無音を削除して時刻を詰めると元音声への参照が難しくなるため、全サンプルと時間原点を保ちます。以前のVADによる入力全体の通過判定では、対象音源で除外がなく、無音の誤生成を解消した根拠は得られませんでした。現在のVADの役割は分割位置の提案です。

ASR本文と音声時刻を同一視できないため、Qwen原文に強制アラインメントを追加します。ただし、警告のない時刻にもずれ得るため、正解時刻として扱いません。安全な細かい時刻が得られない行は該当入力チャンクの範囲を示します。長文が複数チャンクをまたぐ場合も表示範囲を制限し、音源全体を指す巨大な行を防ぎます。この制限は意味の区切りを保証するものではありません。

## 話者候補と実行条件

Community-1は既存のSwift/Core ML構成から利用できる話者候補生成として採用しています。Nemotronに対する精度優位や、全編での話者の正確さが確定したという選定ではありません。選択範囲全体を一度に処理し、短い独立窓ごとの話者番号を連結しません。完全な帰属よりも意味の保持を優先し、不明・混在を残します。

通常処理が音源長以内なら速度より品質を優先します。約200秒は上限ではありません。比較と不具合の切り分けを容易にするため、処理は順次実行します。外部への音声送信と有料APIは使いません。モデル・依存の固定条件は[DEPENDENCIES.md](DEPENDENCIES.md)、確認できた品質と制限は[VALIDATION.md](VALIDATION.md)に記載します。

## 入力と確認対象の同一性

入力ファイルの事前・事後ハッシュが一致しても、正規化中だけ内容が変更されていた可能性は除外できません。通常CLIで元入力を専用の一時領域へコピーし、その実体が記録したSHA-256と一致した場合だけ正規化に渡します。コピーは読み取り専用にし、正規化後または失敗時に削除します。元ファイルの追加コピーを成果物として保管する目的ではありません。処理中は入力容量分の追加空き容量が必要です。

確認票の対象は本文だけでなくAppleとの比較根拠も含みます。成果物IDは対象版の取り違え防止であり、真正性を保証する署名ではありません。構造検査は統合アラインメントと参照先の各子出力を照合します。Apple差分の時刻は元のApple単位の範囲で、Qwenの語時刻や差分内容の正しさへは転用しません。

検査する範囲は、呼出側が覚えているファイル一覧ではなく、実際の読込単位と根拠の参照関係に揃えます。モデルはディレクトリ全体の構成を共通検査し、VADは原出力・分割計画・音声manifest・実チャンクを照合します。原出力のハッシュ一致と、各工程間の内容の整合を別々に確認します。回帰テストの正常系にも必須の根拠ファイルを含め、簡略化したfixtureによって検査の欠落を隠さないようにします。
