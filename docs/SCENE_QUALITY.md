# シーン抽出に使う品質の判断

CLIは未校正の認識文と根拠を生成します。完成した素材から候補シーンを探すことと、その内容を引用・公開できることは別の判断です。

## 重視するもの

1. 主張、理由、具体例、否定、条件、数字、重要な固有名詞が保持される。
2. 質問と回答、主張と反論、経験談の持ち主を取り違えない。
3. 元音声へ戻れる時刻と、前提・結論を落とさない前後の文脈がある。
4. 不明・混在・ASR間の差を発見できる。

表記揺れや意味を変えない挨拶・相づちの欠落は、それだけで候補を捨てる理由にしません。肯定・否定・訂正など内容を変える短い応答は確認対象です。人名付き要約が不要なら、話者不明を残したまま匿名の内容候補を作れます。

## 根拠の強さを分ける

| 確認 | 分かること | 分からないこと |
|---|---|---|
| 構造検査 | サンプル範囲、文字保存、時刻の上下限、出力間の整合 | 音声からASRが落とした内容・話者の正解 |
| Apple/Qwenの照合 | 違う表現・欠落候補 | どちらが正しいか。一致していても同じ誤りがある |
| 人の聴取 | 実際に確認した範囲の内容・話者・再生位置 | 未聴取部分の品質 |

`quality.* = review_required` は未確認です。候補を読むことはできますが、正解と解釈しません。`ready_for_attributed_summary` は重要な内容・話者・境界の確認が揃うまでfalseです。人が確認した範囲だけ、別保存の確認票で判定します。

時刻はQwen強制アラインメントの候補です。警告がない語でもずれる可能性があります。`playback_start/end` の余白は確認の便宜で、精度保証ではありません。VADによる休止候補も、人の息継ぎや語境界を常に意味しません。

## 後段エージェントの使い方

- 質問、主張、理由、具体例をまとめて候補にし、原文の区間IDと秒範囲を残す。
- 内容のない短い応答を要約で省いても、元の認識文は変更しない。
- 名前・否定・数字・強い引用は音声へ戻る。Appleの文を正解として自動移植しない。
- 同一人物か不確かなときに、別クリップのA/Bや実名を結び付けない。
- 聴取していない状態でDER/CER・精度率・全文確認済みなどを作らない。

この作業にAstraが音声から作った独立参照はありません。ユーザーが冒頭180秒の語句訂正を提供していますが、全文・全話者・全境界の正解ラベルではありません。この語句訂正は対象音源の冒頭0–180秒に限るもので、全文置換の辞書や全行の合格には使いません。

| 認識された語句 | ユーザーが示した訂正 |
|---|---|
| 復活 | 深津 |
| 奥さん | 青木さん |
| 北尾さん | 北欧さん |
| 三番目 | 三話目 |
