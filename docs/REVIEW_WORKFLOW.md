# 音声の確認・修正を後段へ渡す

現在は要約の入力品質を検証中です。`review.html` は元音声へ戻るための確認画面で、表示された候補を音声確認済みと扱いません。判定基準は [SCENE_QUALITY.md](SCENE_QUALITY.md)、実験と残る誤りは [今回の全編検証](VALIDATION.md)を参照してください。

## 確認する

1. 対象出力の `review.html` を開く。音声の相対参照先も必要なので、`result/` 単体ではなく親の実験ディレクトリからlocalhostで表示する。
2. 発言の前後を再生し、重要な内容、主要な話者、再生位置を項目別に判定する。一部だけ聴いた行全体を通過にしない。ASRの一致だけで通過にしない。
3. 誤りはメモに記録し、「聴いて確認した修正」で本文・話者・時刻を必要な分だけ直す。判定は修正後の内容に対するもの。複数話者の言葉を分けられない行は話者不明を保持する。
4. 確認者の呼び名と、実際に聴いた元音声上の秒範囲を記入する。例: `33.9-124`。複数範囲は改行で区切る。
5. 「確認票JSONを表示」で本文を確認し、「JSONをダウンロード」で別ファイルへ保存する。ダウンロードできない場合は「JSONをコピー」、自動コピーも使えなければ「JSONをすべて選択」→ `⌘C` で取り出せる。確認者と聴取範囲は必須で、再生しただけでは自動記入されない。入力エラーはボタンの下に表示される。既存の文字起こし・モデル原出力は変更されない。

保存ボタンの操作だけではファイル保存の完了を確認できないため、画面も「ダウンロードを要求しました」と表示する。フォームを変更した場合はJSONを再表示する。旧実験のHTMLは上書きしないので、新しいボタンがない場合は最新の確認ページを使う。

会話で聴取結果を受け取った場合も、発言そのものと対象版を記録して確認票へ転記できる。[ローカル保管資料](../archive/README.md)にある冒頭180秒の語句訂正では、語句訂正を適用し、報告されていない話者・境界・行全体の合格は未確認のまま残した。

話者の帰属を必要としない内容なら、話者を「対象外」にして理由を記録できます。これは話者が正しいという意味ではありません。短い発言も、否定・訂正・重要な補足なら内容確認の対象です。

## 確認票を反映する

確認した画面と同じ実験・版の `transcript.json` を指定し、未作成の出力先を使います。

```sh
python3 scripts/apply_scene_review.py \
  runs/scene-new-intro/result/transcript.json \
  /path/to/scene-quality-review.json \
  runs/scene-new-intro-reviewed
```

| 出力 | 用途 |
|---|---|
| `transcript-reviewed.json` | 未確認行も残した全体。修正前の行、修正内容、確認者、日時を保持 |
| `ready-segments.json` | 内容・境界を明示的に通過した部分集合。話者の確認状態によって匿名用／帰属付き用を区別 |
| `review.json` | 受領した確認票そのもの |
| `application.json` | 元ファイルのSHA-256、対象artifact ID、適用件数 |

画面の元データ、音声hash、行の元値、確認者・日時・聴取範囲を検査します。別の版への誤適用、範囲外の判定、不正な話者ID・時刻を拒否します。修正後の文字と元のASR unitは一対一とは限らないため、手動修正後の文字に元の細かな時刻を流用したとは主張しません。

`ready_for_anonymous_summary=true` は内容・境界が通過し、話者が通過または理由付き対象外の行です。`ready_for_attributed_summary=true` はさらに単一の話者IDが通過した行です。これらは人の確認記録に基づく状態で、実際に聴いたことをプログラムが証明する仕組みではありません。未確認・不合格の行は利用可能な部分集合へ入りません。

一部が通過しても全文を合格にしません。独立クリップのA/Bはそのまま連結せず、`speaker_identity_scope` を引き継ぎます。後段では元音声hash・秒範囲・確認記録を出典として保持してください。要約やシーンの順位付けそのものは、このCLIでは実行しません。

古い `review-v3` 等の確認票にはこの照合用IDがありません。現在の画面から確認票を作成し、古い票を検査なしに移し替えないでください。
